# 高股息策略扫描器 V3

基于《安全吃股息 —— 银行·电力·公用事业股息率投资系统 V3.0》实现的全自动高股息选股程序。
每个交易日收盘后自动跑一遍，生成手机可直接打开的静态 HTML 报告。

## 一、这是什么

不是「股息率大于 4% 就买」的简单筛选，而是把原书的四层策略引擎完整实现：

| 模块 | 文件 | 职责 |
|---|---|---|
| 股票池 | `pool.py` | 115 只标的的分类、子类、DPS 模式、三档股息率门槛、行业上限 |
| 策略引擎 | `strategy.py` | 四种 DPS 计算、三档买点、状态判定、假高股息识别、安全校验 |
| 数据层 | `data_source.py` | 腾讯行情 + 巨潮分红历史，带磁盘缓存 |
| 主程序 | `screener.py` | 扫描全池并渲染 HTML 报告 |

## 二、核心逻辑

### 1. 四种 DPS（每股分红）

| 类型 | 算法 | 用途 |
|---|---|---|
| 最新 DPS | 最近一个完整年度的分红 | 参考 |
| 保守 DPS | min(最近三年年度 DPS) | **定价基准** |
| 正常化 DPS | min(五年中位数, 三年均值×80%, 三年最低) | 周期股参考 |
| 压力 DPS | 保守 DPS × 0.80 | 极端情形测算 |

「完整年度」要求该年**年报分红已实施**（除权日已发生），避免把中期分红当成全年。

历史每股分红已做**送转复权**：若某年之后发生过送股/转增，按比例回溯放大，保证跨年可比。

### 2. 三档买点

```
首仓价 = 定价 DPS ÷ 首仓股息率    仓位 30%
加仓价 = 定价 DPS ÷ 加仓股息率    仓位 30%
重仓价 = 定价 DPS ÷ 重仓股息率    仓位 40%
```

股息率门槛按「类别 + 子类」区分。例如：

| 子类 | 首仓 | 加仓 | 重仓 |
|---|---|---|---|
| 六大行 | 4.5% | 5.2% | 6.0% |
| 标准股份行 | 5.0% | 6.0% | 7.0% |
| 顶级大型水电 | 3.3% | 3.8% | 4.5% |
| 核电 | 3.5% | 4.2% | 5.0% |
| 核心高速 | 4.0~4.2% | 4.7~5.0% | 5.5~5.8% |
| 通信运营商 | 4.0~4.5% | 4.7~5.2% | 5.5~6.0% |
| 内贸航运 | 7.0% | 8.0% | 9.5% |

> PE / PB 只用于**事后检查**，不作为买点触发器（原书第 16 章）。

### 3. 假高股息识别

命中任一项会打标，已到加仓/重仓档的会被**降级为首仓档（需核实）**：

- 股价暴跌型：静态股息率异常高但 DPS 在下滑
- 周期顶部型：静态股息率显著高于正常化股息率（仅对周期股启用）
- 特别分红型：分红含一次性特别派息
- 高支付率型：分红 ≥ 净利润
- 借债分红型：经营现金流 < 净利润 50% 且支付率 > 50%
- 除息错觉型：近期刚除权

### 4. 分红下降分级处理

| 降幅 | 判定 | 处理 |
|---|---|---|
| ≤10% | 正常波动 | 维持 |
| 10~25% | 趋势弱化 | 降档观察 |
| >25% | 结构恶化 | 暂停买入 |
| 取消分红 | 退出信号 | 移出池子 |

### 5. 行业上限（第 33 章）

银行 35~50%、电力 20~30%、公用事业 15~25%、周期与机会 0~10%、战略现金 10~30%。

## 三、股票池：115 只

| 来源 | 数量 | 说明 |
|---|---|---|
| 原书附录 A | 76 只 | 作者已做基本面筛选 |
| 扩展池 | 39 只 | 按同样的行业框架补充 |
| **合计** | **115 只** | |

扩展池标的在报告里带**「扩展」**灰色标签，判定结论会标注**「（扩展池）」**——因为它们没有经过原书作者的基本面筛选，到买点也需要人工复核后再动手。

板块分布：银行 38 · 公用事业 48 · 电力 24 · 周期相关 2 · 强周期 1 · 非主系统 2。

> 周期评分已按需求**关闭**，`pool.py` 中全部 `cycle` 标记为 `False`。

## 四、本地运行

```bash
pip install -r requirements.txt
python screener.py              # 扫描全池并生成 docs/index.html
python screener.py --limit 20   # 只跑前 20 只（调试用）
python screener.py --clear      # 清缓存后跑
```

产物：
- `docs/index.html` —— 手机可直接打开的静态报告（无 JS，微信内置浏览器可正常显示）
- `docs/data.json` —— 结构化结果
- `history.json` —— 与上次快照对比，用于「NEW」标记

## 五、GitHub Actions 自动更新

`.github/workflows/daily.yml`：每个工作日 UTC 09:00（北京时间 17:00，收盘后）自动运行，
并把更新后的 `history.json`、`docs/index.html`、`docs/data.json` 提交回仓库。

首次使用需要在仓库 **Settings → Actions → General → Workflow permissions** 里
勾选 **Read and write permissions**，否则无法提交。

## 六、数据来源

- 行情 / PE / PB / 52 周高低 / 换手率：腾讯财经 `qt.gtimg.cn`（批量 50 只一次请求）
- 分红历史：巨潮资讯 `stock_dividend_cninfo`（AKShare 封装）
- 财务摘要：AKShare `stock_financial_abstract`

缓存策略：行情 10 分钟、分红与财务 3 天。免费接口偶有波动，失败会自动重试并跳过。

## 七、风险提示

本程序是**决策辅助工具**，不构成投资建议。免费数据源存在延迟与误差，
买点判定依赖历史分红外推，不代表未来实际派息。请务必自行复核后再决策。
